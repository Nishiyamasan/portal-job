# portal-job (ポータルジョブ) 

> **地元の店舗と求職者を繋ぎ、持続可能な地域経済と業務の効率化を実現するプラットフォーム**

---

## 概要

**portal-job** は、地域に根ざした個人店・中小規模事業者（レストラン、カフェ、食堂など）と、その地域で働きたい求職者をダイレクトに結びつける、次世代型マルチエリア・マッチングプラットフォームです。

単なる「求人情報の掲載」に留まらず、リアルタイムの**portal-job Chat**、および店舗の魅力を発信してイメージを高める**メディア管理システム**を統合し、地域社会における「雇用」と「マッチング」の課題をワンストップで解決します。

---

## 課題解決のための開発背景

地方自治体や特定地域コミュニティにおける経済の持続可能性は、地元の店舗（カフェ、和食、洋食、食堂等）の活性化に直結しています。しかし、現在の地域社会は以下の深刻な課題に直面しています。

1. **求人媒体の掲載料高騰とアンマッチ**
   大手求人サイトは月々の掲載料が高額であり、地元の個人経営店や小規模事業者は持続的に募集を出すことが困難です。
2. **求人掲載の手続きや店舗情報の更新コスト**
   小規模店舗において、求人情報の追加や修正、魅力的な店舗イメージの発信を手軽に行えるITツールが不足しており、情報発信が滞りがちになっています。
3. **地域内のつながりの希薄化**
   地元のファンやリピーターが「その店で働きたい」と思っても、店舗と求職者の間に安全で迅速なコミュニケーション（チャット等）の手段がありませんでした。

**portal-job** は、これらの「コスト」「情報発信」「コミュニケーション」の壁を取り払い、地域コミュニティ内での最適なマッチングを推進するために開発されました。

## レイヤー別アーキテクチャ

本プロジェクトは、スケーラビリティ、パフォーマンス、関心の分離（SoC）を追求した多層アーキテクチャを採用しています。

```
├── src/                    # フロントエンド (Next.js 15 App Router)
│   ├── app/                # Localized Page Routing (next-intl, [locale])
│   ├── components/         # 共通UI & ドメイン特受のコンポーネント群
│   │   ├── ui/             # Atomicなデザインシステム（Modal, Skeleton等）
│   │   └── ...             # 各ビジネスドメインのUI/UX（チャット、店舗管理等）
│   └── lib/                # API通信 (Supabase JWT連携), カスタムフック
├── go-api/                 # メインAPIサーバー (Go 1.22+ / pgxpool)
│   ├── cmd/                # エントリーポイント
│   └── internal/           # データベース、認証、CORS、ルーティング
├── go-worker/              # バックグラウンドタスクランナー (Go)
│   └── internal/tasks/     # ジョブ自動期限切れ処理、Webプッシュ配信統計
└── backend/                # 補助用高速Webサーバー (Python FastAPI / SQLAlchemy)
```

### バックエンドAPIの実装（Go & Python）

本プロジェクトでは、同一の要件に対して、**Go**（`go-api`）と**Python/FastAPI**（`backend`）の2種類のバックエンドAPIをダブル実装しています。これにより、各言語のパフォーマンス特性や開発体験の比較、インフラ要件に応じた柔軟な構成選択が可能です。

- **Go (現在採用中)**: `go-api` ディレクトリ。軽量かつ高速な実行速度と、`pgxpool` による高効率なデータベース接続プールを活用しています。
- **Python (FastAPI)**: `backend` ディレクトリ。記述性の高さと、`SQLAlchemy` ORM を活用した素早いスキーマ構築・拡張性が特徴です。

#### バックエンドの切り替え方法

デフォルトの `docker-compose.yml` では、メインで採用している **Go バックエンドのみが起動**するように設定されています。Python (FastAPI) バックエンドを使用する場合は、以下の手順を実行してください。

1. `docker-compose.yml` を開きます。
2. `services:` 配下の `# Python REST API (FastAPI) バックエンド` のコメントアウト（`backend:` から `start_period: 30s` まで）を解除します。
3. `docker compose up -d --build` で起動します。

## 開発環境のセットアップ

### 1. 環境変数の設定
プロジェクトルートにて、環境変数設定ファイルを作成します。
```bash
cp .env.sample .env
```
`.env` 内の各項目（データベースURL、Supabase、Cloudinary情報など）を、自身の開発用環境に合わせて編集します。

### 2. ローカル開発用コンテナの起動
Docker Composeを使用して、バックエンド（Go/Python）やデータベースをまとめて立ち上げます。
```bash
docker compose up -d --build
```

### 3. フロントエンドの個別実行
```bash
npm install
npm run dev
```

### 4. 静的コード解析とビルド検証
```bash
# 型チェック
npx tsc --noEmit

# リンター
npm run lint

# E2Eテストの実行
npm run test:e2e
```

��発時の残存データを完全に一掃し、すべてクリーンなプレースホルダーおよびテスト用ダミーデータに統一しました。

  バックエンド（Go/Python）およびインフラ設定（`docker-compose.local.yml`）において、`${VARIABLE:-default_value}` の形式に徹底的にリファクタリングし、万が一環境変数が未指定の場合でも安全にフォールバック、または安全な起動シグナルを出せるように設計を統一しました。
- **プロジェクトルートに `.env.sample` を配置**:
  新規開発者が即座に安全なローカル開発環境を再現できるよう、詳細なコメントと適切なプレースホルダー付きの環境変数サンプルを完備しました。
