# portal-job (ポータルジョブ) 

> **地域の店舗とユーザー（観光客・ワーカー）を繋ぐ、店舗の魅力を高め、業務の効率化を実現するプラットフォーム**

---

## 概要

**portal-job** は、地域に根ざした個人店・中小規模事業者（レストラン、カフェ、食堂など）と、その地域を訪れる観光客（訪日外国人含む）や働きたい人をダイレクトに結びつける、地域活性化プラットフォームです。

店舗情報、求人情報、リアルタイムの**Chat**、および店舗の魅力を発信することで、地域社会における「雇用」と「インバウンド対応・情報発信」の課題を解決します。

## 課題解決のための開発背景

地方自治体や特定地域コミュニティにおける経済の持続可能性は、地元の店舗（カフェ、和食、洋食、食堂等）の活性化に直結しています。しかし、現在の地域社会は以下の深刻な課題に直面しています。

1. **求人媒体の掲載料高騰**
   大手求人サイトは月々の掲載料が高額であり、地元の個人経営店や小規模事業者は持続的に募集を出すことが困難です。
2. **求人掲載の手続きや店舗情報の更新コスト**
   小規模店舗において、求人情報の追加や修正、魅力的な店舗イメージの発信を手軽に行えるITツールが不足しており、情報発信が滞りがちになっています。
3. **情報発信の言語の壁と限界**
   訪日外国人や観光客に対して、「情報発信スペース（メディア機能）」が不足しており、魅力が伝わりきっていません。また、日本語のみの発信では言語の壁が生じ、機会損失となっています。将来的にはLLMを活用した多言語での自動情報発信や問い合わせ対応（RAG / AIエージェント）を導入し、世界に向けて店舗の魅力を発信できる環境を目指しています。

## 技術的アプローチ

### 1. BFF / 多層レイヤーアーキテクチャ
*   **フロントエンド (Next.js 15 App Router)**: Edge Runtime による高速なレスポンスと、`next-intl` による多言語対応。
*   **バックエンド (Go 1.22 / pgxpool)**: 軽量かつ高速な実行速度と、コネクションプールによる高効率なDB接続。
*   **バックエンド（API）**: 構成の比較検証のため、Go（`go-api`）とPython/FastAPI（`backend`）の2種類のAPIサーバーを用意（現在はGo版を採用中）。

### 2. インフラ・運用のコード化 (IaC / CI-CD)
*   **Terraformによる構成管理**: インフラ設定を `infra/main.tf` で完全にコード管理。
*   **GitHub ActionsによるCI/CD**: 
    *   **CI (品質チェック)**: プッシュ・PR時に自動でLint（静的解析）、TypeScriptの型チェック、および Go バックエンドのビルド・単体テストを実行。
    *   **CD (デプロイ)**: `main`ブランチへのマージ時に Docker イメージの自動ビルドおよびコンテナレジストリ（GHCR）への自動プッシュを実行。

## レイヤー別ディレクトリ構成

```
├── src/                    # フロントエンド (Next.js 15 App Router)
│   ├── app/                # 多言語ルーティング (next-intl, [locale])
│   ├── components/         # 共通UI & ドメイン特有のコンポーネント（チャット、店舗管理等）
│   │   └── ui/             # Atomicデザインシステム（Modal, Skeleton等）
│   └── lib/                # APIクライアント、Supabase JWT認証、カスタムフック
├── go-api/                 # メインAPIサーバー (Go 1.22+ / pgxpool)
│   ├── cmd/                # エントリーポイント
│   └── internal/           # データベース、認証、CORS、ルーティング
├── go-worker/              # バックグラウンドタスクランナー (Go)
│   └── internal/tasks/     # バッチ処理（求人の自動期限切れ処理等）
└── backend/                # 補助用高速Webサーバー (Python FastAPI / SQLAlchemy)
```

## 開発環境のセットアップ

### 1. 環境変数の設定
プロジェクトルートにて、環境変数設定ファイルを作成します。
```bash
cp .env.sample .env
```
`.env` 内の各項目（データベースURL、Supabase、Cloudinary情報など）を編集します。

### 2. フロントエンドの個別実行
```bash
npm install
npm run dev
```

### 3. 静的コード解析とビルド検証
```bash
# 型チェック
npx tsc --noEmit

# リンター
npm run lint

# E2Eテストの実行
npm run test:e2e
```
